# Очереди заявочного ремонта

Новые обращения, созданные в журнале или поступившие через существующий импорт Яндекс Форм, сначала направляются только в участок заявочных ремонтов. Очередь работающей смены определяется по московскому времени и сохранённому графику 2/2. Для ночной смены до 08:00 используется рабочая дата предыдущего дня. Назначение не зависит от часов браузера.

Если активного профиля текущей смены нет, обращение остаётся в общем профиле участка. При ручном создании также можно явно выбрать общий профиль. Общий профиль видит заявки участка, включая очереди конкретных смен; сменный профиль видит свою очередь. Остальные участки получают доступ после передачи им заявки. Руководство видит общий журнал, но решения принимает по переданным ему на рассмотрение обращениям. Администратор сохраняет полный доступ.

Назначенная очередь сохраняется при смене календарного дня. Невыполненная заявка не уходит автоматически следующей смене: мастер передаёт её явно, указывая выполненное, оставшиеся работы и причину.

Действия владельца:
- Принять в работу.
- Оставить в ожидании с причиной.
- Передать другому участку.
- Передать другой смене того же участка заявочных ремонтов или в общий профиль.
- Отправить руководству на рассмотрение с вопросом и причиной.
- Назначить плановый ремонт внутри своего участка на выбранную дату; для заявочного ремонта выбирается также смена.
- Добавить заметку.
- Отклонить с обязательным объяснением.

Передача участку или смене возвращает заявку в очередь «Ожидает решения» получателя. Другой участок не получает сменную модель: четыре смены относятся только к заявочному ремонту. Во время рассмотрения руководством предыдущий участок не может менять заявку; руководство возвращает её в работу выбранному участку/смене, планирует ремонт либо отклоняет.

Завершение ремонта доступно после принятия в работу и требует описания выполненных работ. Отклонённая заявка сохраняется в истории борта с причиной, но не увеличивает число выполненных ремонтов. История решений и заметок сохраняется после закрытия и включена в выгрузку Excel и полную резервную/переносимую копию. Завершение заявки не заменяет установленный на предприятии порядок допуска машины и выпуска на линию.

Каждое решение фиксирует время, профиль, смену, участок, причину и результат. Проверка версии предотвращает перезапись чужого решения при одновременной работе. Физическое наличие сотрудника система не подтверждает: активный профиль означает настройку доступа, а не отметку присутствия.

Заявки, существовавшие до обновления, остаются у прежних участков. Они получают журнал событий при первом новом решении. Ранее существовавшая общая очередь заявочного ремонта остаётся доступной сменам до принятия или явного назначения; при принятии сменой она закрепляется за ней.

Внешнюю форму для водителя, отправку сообщений по почте/SMS, учёт присутствия, запрет планирования на выходной смены и автоматический перенос просроченных заявок это обновление не добавляет. Импорт из уже настроенной Яндекс Формы использует новую очередь при получении, а не задним числом по дате старого ответа.

## Заметки ремонта

Отдельные заметки добавляются через «Добавить заметку». Автор и администратор могут удалить заметку, пока ремонт открыт и профиль имеет доступ к управлению этой заявкой. После закрытия оставшиеся заметки доступны только для чтения. Заметки, созданные до появления учёта авторов, может удалять администратор.

В истории ремонтов и в карточке машины можно открыть конкретный ремонт и увидеть выполненные работы, неудалённые заметки и журнал решений. В Excel отдельный лист «Заметки ремонта» содержит только неудалённые записи.

Удаление скрывает текст заметки из рабочих карточек, истории ремонта и пользовательской выгрузки. В журнале остаётся факт удаления без текста. Исходная запись сохраняется в служебных данных и резервных копиях для аудита. Причины передачи, отклонения и другие решения не являются удаляемыми заметками.
